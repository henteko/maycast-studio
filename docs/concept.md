# Maycast Studio コンセプト

## 概要

**Maycast Studio** は、Podcast 配信者向けの macOS デスクトップアプリケーションです。Podcast 制作に必要な「最低限の編集」を、手軽に・素早く・高品質に行うことを目的としています。

- **対象 OS**: macOS
- **開発言語/フレームワーク**: Swift + SwiftUI
- **ライセンス**: OSS (Open Source Software) として公開
- **ターゲットユーザー**: 個人 / 小規模チームの Podcast 配信者

## コンセプト

> **「最低限の編集を手軽に」**

Podcast 制作の現場では、DAW (Digital Audio Workstation) のような高機能ツールはオーバースペックであり、学習コストも高くなりがちです。一方で、無音削除・ノイズ除去・音量正規化・BGM/Intro の合成といった「Podcast に必須の最低限の編集」は、毎回のエピソード収録のたびに発生します。

Maycast Studio は、これら「最低限の編集」をシンプルな UI と自動化で完結できることを目指します。プロ向けの細かい操作ではなく、配信者が「録音 → 公開」までを最短距離で到達できるワークフローを提供します。

## アーキテクチャ方針

### XPC によるプロセス分離

Maycast Studio の各機能 (Slice / Polish / Mix) は、SwiftUI アプリ本体とは独立したプロセスとして XPC で分離します。

**狙い**:

- **安定性**: 重い音声処理が UI プロセスをブロックしない / クラッシュが本体に波及しない
- **再利用性**: 同じ機能を GUI / CLI / 自動テストの 3 経路から呼べる
- **責務分離**: GUI 層は「見せ方」、XPC サービス層は「処理ロジック」に専念できる

### CLI からの操作

Xcode と `xcodebuild` の関係のように、Maycast Studio (GUI) と対になる CLI ツール `maycast` を提供します。CLI は GUI と同じ XPC サービスを呼び出すため、機能の挙動が完全に一致します。

**狙い**:

- **AI エージェント連携**: Claude Code などの AI エージェントから CLI 経由で Maycast Studio の各機能を呼び出せる
- **E2E テスト**: GUI を介さずに音声処理パイプライン全体を自動テストできる
- **スクリプタビリティ**: CI / 定期処理 / バッチ処理に組み込める

### 構成イメージ

## 機能 (Maycast Studio)

### 1. Slice — 編集

マルチトラック音声ファイルの基本編集機能。

- トラック単位の **分割 / 削除 / 移動**
- **文字起こし結果を見ながら編集** できる UI (発話単位での切り貼り)
- 「言い淀み」「録り直し」箇所をテキストベースで素早く特定・削除

### 2. Polish — クリアリング

Podcast に必要な音声クリーニングを自動化。

- **無音区間の削除** (閾値ベース)
- **背景ノイズ除去**
- **音量/音域の一定化** (ラウドネス正規化、コンプレッション)
- その他 Podcast 向けの音声処理 (de-esser, ハイパス等)

### 3. Mix — 合成

複数トラック + Intro/Outro/BGM を結合し、配信用の 1 本の音声に仕上げる。

- マルチトラックの結合
- **Intro / Outro / BGM の重畳**
- 話者音声と BGM が重なる区間は **自動で音量調整 (ダッキング)**
- Intro / Outro の **被り区間は手動で微調整可能**

## 将来構想 — Maycast Cloud (外部 Web サービス連携)

Maycast Studio はローカル完結を基本としつつ、将来的に Web サービス **Maycast Cloud** と連携する拡張を予定しています。

### Room — リモート収録

- WebRTC ベースで話者同士を接続
- **収録自体は各話者のローカルで行う** (= ネットワーク影響を受けない高音質収録)
- 収録後に各ローカル音源をクラウドへアップロードし、Maycast Studio で編集

### Knowledge — エピソードナレッジ管理

- 過去エピソードの概要を蓄積
- 今後話したいネタの DB (手動登録)
- 蓄積データをもとに **次回エピソードのネタを推薦**
- ネタの管理 (採用/保留/没) もここで完結
